**决策：** D21–D26（`implementation-tasks/V1_6_DECISIONS.md`）

## 0. 背景与实测证据

2026-09-01/02 产品负责人以 DeepSeek（`deepseek-v4-flash-vision-exp`，`https://api.deepseek.com`）实测 AI 功能，"测试连接"与"AI 修改"全部失败。经以真实工作区数据与已保存 Key 复现（Key 全程仅内存使用，未打印未落盘），根因如下：

1. **测试连接**（`ai-gateway.ts` `testConnection`）发送 `max_tokens: 1` 的 `ping`；DeepSeek V4 系列默认开启 thinking（`reasoning_content` 与 `content` 同级、计入 completion tokens），唯一的 1 个 token 被思维链消耗，`content` 为空 → 网关解析器要求 content 非空，抛 `AI_INVALID_RESPONSE`（"AI 服务返回了空响应"）。实测：同一请求加 `thinking: {"type":"disabled"}` 即正常返回。
2. **AI 修改整张讲义**：两阶段（方案 → 确认后生成）均以 `max_tokens: 2000` 发送；实测思维链 3,000+ 字符起步，2000 token 预算全部被 `reasoning_content` 消耗（`finish_reason: length`），正文 0 字 → 同样判空报错。
3. **普通生成**侥幸可用（简单任务思维链仅 ~60 token），但属同一根因的较轻表现，随时可能翻车。
4. 修改链路的渲染层基线读取（`draft-panel.tsx` `readScopedTextParts`）只认 `kind === 'text'`（md/txt），docx/pdf/pptx 返回 unsupported 被跳过 → 以外部 office 文件为修改对象时报"没有可读文本"。产品负责人裁决：**不做此通路**，AI 修改仅面向应用内生成的 Markdown 课件版本（D23）。
5. 参考资料解析现状：officeparser 纯文本抽取对数学公式（OMML）、扫描件、题目照片无能为力（`ocr: false`、图片跳过）；实测工作区内约 30 张题目 PNG 对 AI 完全不可见。
6. 实测吞吐与成本：DeepSeek 输出 ~2,300 token/s；12000 字上下文 + 2000 token 输出 257ms 返回；满 30,000 字上下文 + 8,000 token 输出估算 < 60s、单次成本 < ¥0.5（产品负责人接受"贵点就贵点"）。

## 1. 产品负责人已确认的范围裁决（对应 D21–D26）

1. **thinking 不关闭**：课件生成的推理质量优先，接受成本与延迟（D21）。
2. **流式输出替代"死等"体验**：老师看得见 AI 在工作（思考进度 + 正文逐字上屏）即可自行判断卡死；超时改为"静默超时"语义（D22）。
3. **AI 修改仅面向应用内生成的文件**（讲义/教案/作业等 Markdown 版本）；外部 docx/pptx/pdf 由老师用 Office/WPS/网页版自行修改，应用不打通其修改链路（D23）。
4. **文档解析接入 MinerU 云端 API**（数学 OCR：公式转 LaTeX、表格结构、扫描件/图片识别）。教学资料无隐私顾虑，产品负责人明确批准上云。凭据走应用内设置（同 AI Key 的 safeStorage 模式），用户自带 token（D24）。
5. **上下文预算 30,000 字、参考文件 ≤10 份、超量明确提示**，不再静默截断（D25）。
6. **Anthropic 格式、docx 导出、vision 直读图片**不在本版（D26 非目标）。

## 2. 技术方案

### 2.1 V16-A · 网关预算修复与测试连接判定修正（救活现有功能）

- **测试连接判据**：成功改为"HTTP 200 且响应为合法 chat.completion 结构"（`choices` 数组存在即可），不再要求 `content` 非空；`requestText` 的 content 非空校验保持不变（业务请求必须拿到正文）。连通性检查与正文质量解耦，思考型后端 `max_tokens` 较小时 content 为空属正常行为。
- **超时**：`AiGateway` 默认超时由内联 `15_000` 提升为命名常量 `DEFAULT_AI_TIMEOUT_MS = 120_000`（`AiGatewayOptions.timeoutMs` 注入点不变，测试继续注入短超时）。
- **预算常数**（`src/shared/draft-contracts.ts`）：
  - `DRAFT_DEFAULT_MAX_CHARS` 12,000 → **30,000**（合同上限 `DRAFT_MAX_CHARS = 100_000` 不变）；
  - `DRAFT_DEFAULT_MAX_TOKENS` 2,000 → **16,000**（合同上限 `DRAFT_MAX_TOKENS = 32_000` 不变；覆盖实测思维链 3,000+ 字符 + 整篇输出 2,000–8,000 token 并留余量）。
- **thinking 保持开启**：请求体不发送 `thinking`/`reasoning_effort` 参数（尊重 D21；DeepSeek 默认 enabled）。
- 同步更新受影响测试（网关超时值、默认常数引用、testConnection 判据）。

### 2.2 V16-B · AI 修改范围收口与参考预算 UX（合同小扩展 + Renderer）

- **修改对象收口（D23）**：
  - 单文件修改的候选目标仅列出应用内生成的文件（课件版本、AI 修改节点，均 Markdown）；外部导入的 office/pdf 文件不出现在"修改这份"目标里，入口处直接置灰/隐藏并提示"仅支持修改工作台生成的讲义/教案/作业；外部 Office 文档请用系统应用打开修改"（现状 `readContent` 返回 unsupported 是生成时的兜底，收口后该兜底不再被触发）；
  - 课次尚无任何应用内版本时，"修改这份 / 整课重做"入口显示引导"先用 AI 生成第一版课件"，跳转对应流程；"AI 新建备课"入口保持现状。
- **参考预算（D25）**：
  - 新合同常量：`DRAFT_MAX_REFERENCE_FILES = 10`（补充参考上限）、`DRAFT_MAX_SOURCE_FILES = 32`（`GenerateDraftRequest.sources` 总长度合同守卫 1..32，覆盖整课模式的自动基线 + 10 份参考）；
  - 选择区实时显示占用：每份候选参考显示字符数（利用既有 `readContent`），汇总"参考已占用 N / 30,000 字"；超过 10 份禁止继续勾选并提示；
  - 发起前超量检查（方案阶段与确认生成共用同一纯函数预算模块，抽入 `draft-scope.ts` 或新纯模块，D14 先例）：预算 30,000 字耗尽时**明确列出**"以下文件未纳入：…"并需老师确认继续或删减，替代现状的静默截断 + 角标提示；基线文件优先占用预算（现状语义保留），参考按选择顺序分配剩余预算；
  - 生成阶段 Main 侧 `buildContext` 的 `maxChars` 截断行为不变（Renderer 明示后 Main 兜底照旧，双层保险）。
- **合同**：`isGenerateDraftRequest` 增加 `sources` 长度上限校验；无新 IPC 通道。

### 2.3 V16-C · 流式生成 IPC 与渲染（新推送通道，D22）

- **合同**（`src/shared/ai-contracts.ts`）：
  - `AiTextRequest` 增加可选键 `stream?: true`（缺省 = 非流式，既有行为与测试不变）；
  - 新增 `AiStreamEvent`：`{ requestId; kind: 'reasoning' | 'text' | 'done' | 'error'; text?: string; chars?: number; model?: string; code?: string }`（守卫 `isAiStreamEvent`）；
  - 新增推送通道 `ai:stream-event`（Main→Renderer 单向推送，进 `AI_IPC_CHANNELS` 白名单与 `ipc-security` 覆盖面）。
- **Main**（`ai-gateway.ts`）：
  - `requestStreamText(requestId, prompt, maxTokens, onEvent)`：请求体加 `stream: true`、`Accept: text/event-stream`；流式读取响应体逐行解析 SSE（`data: {…}` → `choices[0].delta.reasoning_content` 归 `reasoning` 事件、`delta.content` 归 `text` 事件；`data: [DONE]` 归 `done`；心跳/空行/坏行跳过）；
  - **静默超时**：任何 chunk 到达即重置计时，连续 `AI_STREAM_IDLE_TIMEOUT_MS = 30_000` 无 chunk 才 abort 报 `AI_TIMEOUT`；总时长不设上限；
  - `cancel(requestId)` 原样复用（同一 AbortController）；
  - `reasoning` 事件只推进度计数（Main 累计字符数），**不转发思维链原文**（D21/D22：思维链不展示给老师）；`text` 事件逐块转发；
  - 非流式 `requestText` 保留（设置面板测试连接、合同不变路径继续使用）。
- **IPC**（`ai-ipc.ts`）：`requestText` 载荷含 `stream: true` 时改走 `requestStreamText`，chunk 经 `event.sender.send('ai:stream-event', payload)` 推送（载荷经 `isAiStreamEvent` 校验后发送）；最终 invoke 响应仍返回完整 `{text, model}`（最终 note 内容以此为准，推送事件仅作进度渲染，规避 SSE 与结果不一致）。
- **Preload**（`preload/index.ts`）：新增 `ai.onStreamEvent(callback): () => void` 订阅并返回退订函数（渲染层按 requestId 过滤）；白名单注册新通道。
- **Renderer**（`draft-panel.tsx`）：生成、方案生成、确认生成进入"生成中"面板：思维链阶段显示"AI 思考中…（已思考 N 字）"进度（`reasoning` 事件累计）；首个 `text` 事件起正文逐字上屏（只读预览，完成后进入现有编辑/对比流程，发布与版本语义零变化）；取消按钮复用现有 `ai.cancel`。
- **测试**：fake 流式 fetch（分块 ReadableStream）断言 chunk 序列、reasoning 计数、done 组装、取消与静默超时；既有非流式测试不动。

### 2.4 V16-D · MinerU 文档解析集成（migration v16 + 新 Service + 新 IPC，D24）

- **安全凭据（多槽 safeStorage）**：`secure-storage.ts` 泛化 slot 维度（`teacher-workbench-<slot>-key.bin`，slot ∈ `{ai, mineru}`）；现有 `teacher-workbench-ai-key.bin` 路径即 ai 槽，**不迁移不改名**。新增 `src/main/ai/mineru-settings-service.ts`（复制 `ai-settings-service.ts` 模式：get/update/clear token；无 DB 行、无 endpoint/model）。
- **设置 IPC**：新增 `mineru:get-settings` / `mineru:update-settings` / `mineru:clear-token` / `mineru:test-connection`（载荷守卫同 ai 系样板；测试连接 GET `/api/v4/extract-results/batch/<不存在ID>`，非 A0202/A0211 即通过——本轮已实测验证的轻量判活法）。
- **设置 UI**（`settings-panel.tsx`）：新增"文档增强解析（MinerU）"卡：token 密码框（不回显，留空保持现状）+ 保存 + 测试连接 + 删除；文案注明"token 加密存储于本机，不进入日志与备份"。
- **Migration v16**：`files.index_status` CHECK 扩展追加 `'mineru_ready'`。SQLite 不能 ALTER CHECK，按官方 12 步法在事务内重建 `files` 表（`PRAGMA foreign_keys=OFF` → 建新表 → `INSERT SELECT *` → drop → rename → 恢复 ON）；专项迁移测试钉死：外键关系无损、`index_status` 旧值语义不变、重复运行幂等。
- **Service**（`src/main/parser/mineru-service.ts`，Main 侧异步编排）：
  - `enhanceFile(fileId)`：校验文件 active、`size ≤ 200MB`、token 已配置 → POST `/api/v4/file/upload-urls` 申请链接 → `fetch` PUT 上传 → POST `/api/v4/extract/task`（`is_ocr: true`、`model: 'vlm'`、`language: 'ch'`、公式与表格识别开启）→ 受理即返回；
  - 轮询：GET `/api/v4/extract-results/batch/<batch_id>`（间隔 5s，上限 30 分钟，超时按 `parse_failed` 语义）；轮询定时器为 Main 内存 Map，服务 close/窗口退出时清理；
  - 结果：下载 zip → **fflate** 解压（officeparser 已依赖，零新增依赖；条目路径 resolve 后必须仍在临时目录内，防穿越）→ 取 `full.md` → 走既有 `SearchService` 入库管道（chunks 入 search.db、全文写入、`files.index_status='mineru_ready'`）→ 触发 `files.onContentChanged` 刷新 UI；
  - 下载 URL 校验域白名单（`*.mineru.net` 及实测 CDN 域，实现时以真实响应核实记录）；token 仅注入请求头；
  - 上传对象 = managed 副本；**外部根目录只读资料不提供任何上传入口**（安全边界维持）。
- **任务 IPC**：`mineru:enhance-file`（`{fileId}` → 受理结果）、`mineru:get-status`（`{fileId}` → `{state: 'queued'|'running'|'done'|'failed', message?}`）；状态为拉取式，不做状态推送通道（简化）。
- **Renderer 入口**：素材库/课次资料文件右键菜单增加"增强解析（MinerU）"：token 未配置 → 置灰 + 引导设置；适用对象为 managed 副本中的 office/pdf/图片文件；已 `mineru_ready` 提示"已是增强解析结果"；queued/running 显示进行中。
- **下游自动受益**：`mineru_ready` 文件经既有 `getFileChunks` 进入生成上下文，公式以 LaTeX 文本（`$...$`/`$$…$$`）参与，渲染链路沿用题库/阅读器已有的 KaTeX 处理。

## 3. 安全与数据语义（不可放松项）

- 新增 IPC 通道（`ai:stream-event` 推送 + `mineru:*` 六个 invoke）全部进类型化白名单 + 载荷双向守卫；Renderer 不接触 Node/文件系统/Key 的边界不变；
- MinerU 上传内容 = managed 副本（老师已主动导入工作台的资料），产品负责人已批准上云；外部根目录只读资料**无任何上传入口**；
- MinerU token 与 AI Key 同等安全待遇：safeStorage 加密、仅 Main 内存解密、不进日志（structured-logger 脱敏已覆盖 token 字样）、不进备份（backup-service 不采集 userData 根 key 文件）、不回显；
- zip 安全解压（路径穿越防护）+ 下载域白名单；
- migration v16 重建 `files` 表为事务内原子操作，外键关系与既有行完整迁移由专项测试钉死；`index_status` 新值只增不改旧值语义；
- AI 生成与发布语义零变化：发布仍走既有"新版本保留旧版本"通道（V152-D/V155-D），AI 结果绝不覆盖老师原资料；
- 流式场景最终 note 内容以 invoke 返回的完整 `{text, model}` 为准。

## 4. 非目标（D26）

- 不做 vision 直读图片（`image_url` 内容块）；MinerU 已覆盖 OCR 场景，待使用反馈再评估；

- 不做外部 office 文件的 AI 修改通路（D23）；

- 不做多文件"合成来源"元数据演进、批量增强解析队列（Later）。

## 5. 验收摘要

1. 真实 DeepSeek 配置下：测试连接通过；单文件修改与整课重做两阶段产出完整正文（thinking 保留）；流式思考进度 + 正文上屏可见；取消可用；静默 30s 报超时。
2. 修改对象仅限应用内生成文件；无版本课次有明确引导；外部 office 文件有明确置灰提示。
3. 30,000 字预算 + ≤10 份参考：选择时可见占用，超限明确列名提示，不再静默截断。
4. MinerU：设置卡配置 token → 文件"增强解析" → `mineru_ready` → 公式/表格入索引 → 生成引用其内容；token 不出现在日志/备份/回显。
5. 迁移 v16：既有工作区升级后 files 行、外键、index_status 旧值全部无损；新值仅由 MinerU 流程写入。
6. 全量质量门 + 中继式流式验收 + 隔离冒烟 + DeepSeek/MinerU 两轮真实自测通过；`checkpoint-V1.6-pass` 待产品负责人最终体验确认后创建。

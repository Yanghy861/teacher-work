# V1.7 · MD 课件编辑（AI 二改 + 人工编辑）与题库 AI 选题生成

**基线：** `checkpoint-V1.6-pass`
**日期：** 2026-09-03（产品负责人立项确认）
**决策：** D27–D31（`implementation-tasks/V1_7_DECISIONS.md`）

## 0. 背景

V1.6 冻结后，产品负责人基于真实使用提出三项连续演进的痛点：

1. **AI 修改对象太窄**：D23 收口为"仅应用内课件版本"（` · 第 N 版.md`），但老师的外部 md 讲义（如思源导出、同事分享的 md）同样需要 AI 二次编辑——"不一定必须是通过 AI 生成的才能改"；
2. **md 只读**：发布后的课件版本在阅读器只读，改一个字都要走 AI 修改流；老师需要人工直接编辑，且编辑器必须支持**行级 LaTeX 公式输入、插图、基础 md 排版（字号等）**——这是数学老师的使用习惯（V1.7 立项原话）；
3. **题库与 AI 割裂**：题库（V1.4 接入，`.tqbank` 只读快照，题目带年级/难度/tag 结构化元数据）与 AI 生成完全并联。最终目标："和 AI 描述之后，只要选上参考题库，AI 自动会去参考相对应 tag 的题目，从中选择合适的题目"写入课件，且学生版/教师版双输出。

## 1. 产品负责人已确认的范围裁决（D27–D31）

- **D27 所有 md 可 AI 二改**：修改对象从"应用内课件版本"放宽到**任意 `text/markdown` 的 managed 文件**（含外部导入）；AI 修改产物按版本语义保存，**绝不覆盖原件**；
- **D28 md 人工编辑**：阅读器对 md 提供"编辑/预览"切换；编辑器支持行级公式（LaTeX，预览即渲染 KaTeX）、插图、基础 md 排版（标题/字号、加粗斜体、列表、表格、引用等）；保存语义见 D29；
- **D29 编辑保存语义**（立项时产品负责人待拍板，基准默认推荐项）：**存为新版本**（课件版本链 → 第 N+1 版；外部导入 md → 新副本 `原名（编辑版）.md`，原件只读不动）。不提供"直接改当前版"（打破版本不可变与"不覆盖老师原资料"边界）；
- **D30 题库 AI 自动选题**：生成时勾选"参考题库（AI 自动选题）"，AI 依据描述+课次上下文+题库 facet 摘要输出**结构化检索计划**（JSON，一一映射 `QuestionBankSearchRequest`），Main 本地确定性执行检索，候选题目全文按预算进入第二阶段，AI 从候选**选题写作（不得杜撰题目）**；不引入 function-calling 工具循环（与流式/取消/超时交织复杂，两阶段确定性方案可测试）；
- **D31 学生版/教师版双输出**：题库参与的生成交付两份——教师版含"选自题库（tag/难度）"标注与答案解析；学生版纯题面无标注无答案，可直接印发。实现：教师版为主生成，学生版为**第二次快速生成**（剥离答案/标注），不做本地规则剥离（避免生成格式刚性约束）。

**产品定位（产品负责人 2026-09-03 确认）**：题库由此从"外挂查询页"升格为"AI 生成的知识源"——**产品上一体（题库成为生成输入源），架构上解耦（独立库、窄接口、可缺省：未安装时开关置灰引导，生成体验与现状完全一致）**。不演变为自动组卷/错题本。

**ID 稳定性（已核实，无新增工作）**：`.tqbank` 导出器强制每题具备稳定 `source_uid`（缺失即抛错拒绝导出），`source_uid` 主键 + `source_question_id` UNIQUE 双保险，"一题一 ID"从第一天保证；生成产物中题目以文本固化进 md，不存运行时引用，快照换版不影响历史课件。

## 2. 技术方案

### 2.1 V17-A · 合同与 Main 支撑（md 写路径 + 题库载荷合同）

- **Migration v17**：`notes.note_kind` CHECK 扩展 `'manual_edit'`（人工编辑节点，与 'manual' 并列；notes 表 12 步法重建，FK 守卫沿用 V16-D 修复后的 `runMigrations` 框架）；`files` 表无变化（版本链文件仍是 `text/markdown`）。
- **新 IPC 通道**（白名单 + 载荷守卫，全部走既有 `files:`/`question-bank:` 命名空间）：
  - `files:read-text`（`{fileId}` → `{ content: string }`，仅 `text/*`，纯文本原始 md，不截断不转换；渲染层自行走既有 KaTeX 渲染）；
  - `files:write-version`（`{fileId, bodyMd, summary?}` → `{ file: ManagedFileRecord, version: number }`：校验目标是 active 的 `text/markdown` managed 文件 → 临时文件 + 原子重命名写新版本文件（版本链文件沿用 ` · 第 N 版.md` 命名找下一个版本号；非版本链文件创建 `原名（编辑版）.md` 副本）→ `importToLesson` 语义入当前课次 → 触发 `files.onContentChanged` 刷新 → 搜索索引走既有 `SearchService.indexFile`。**绝不写目标文件自身**——原件只读边界）；
  - `question-bank:search-questions`（`QuestionBankSearchRequest` → `QuestionBankSearchResult`：Renderer 选题计划预览/过目步复用既有搜索；主生成检索在 Main 内部直接调 `QuestionBankService.search`，不经 IPC）。
- **生成合同扩展**（`src/shared/draft-contracts.ts`）：
  - `DraftBankPlan`：`{ text?, tags?, grade?, type?, difficultyMin?, difficultyMax?, targetCount }`（一 clone 即 `QuestionBankSearchRequest` 子集 + 目标题数；`isDraftBankPlan` 守卫，`targetCount` 1..20）；
  - `GenerateDraftRequest` 增可选 `bankPlan?: DraftBankPlan`、`dualVersion?: true`（缺省 = 单版，既有行为不变）；`GenerateDraftResult` 增可选 `studentNoteId?: string`（双版时学生版 note 的 id）；
  - `isGenerateDraftRequest` 相应校验；`DRAFT_MAX_SOURCE_FILES` 不变（题库候选块算**一项参考**，不占文件份数）。
- **题库上下文注入**（`draft-service.ts`）：`buildContext` 扩展——`bankPlan` 存在时：
  1. 调 `QuestionBankService.search`（limit = `targetCount` × 3，offset 0；含图题照常返回，`hasAssets` 传给 AI 供其标注"含图"）；
  2. 候选题目渲染为文本块（`renderQuestionForContext`：题干 + 选项 + 答案 + 解析 + 元数据行"tag/难度/年级/题型/含图"），块头注明"以下为题库候选题（共 N 道，含答案解析；不得杜撰，只能从中选择）"；
  3. 候选块**整块计入 `maxChars` 预算**（作为一项参考参与 D25 基线优先分配；超预算时按 `targetCount` 截减候选数并记录进 metadata）；
  4. `DraftNoteMetadata` 增 `bankSelection?: { plan, retrievedCount, sentCount, candidateIds }`（审计留痕，不存题目全文——全文固化在 note body 里）。
- **AI 检索计划**（阶段一）：`draft-service` 先以现有 `requestText`（**非流式**，短请求）出计划——prompt 含课次标题/学段/老师 requirement + `QuestionBankSummary` 的 facet 摘要（tags/年级/题型/难度范围及计数，Main 直取，零新 IPC）→ 响应经 `parseChatResponse(payload, 'structure')` 风格的 JSON 提取（容错：截取首个 `{...}`，解析失败回退"仅 text 全库检索 + 默认难度"），计划经 `isDraftBankPlan` 校验，非法字段丢弃；
- **学生版生成**（`dualVersion: true` 时）：教师版主生成完成后，构造第二次请求（prompt = "基于以下教师版内容生成学生版：去掉答案解析区块与题库标注，保留题面与讲解，输出格式与教师版一致" + 教师版全文；`maxChars` 同主请求、`maxTokens` 减半；非流式即可，学生版无流式面板要求），产出存为同课次 note（`note_kind` 同主 kind），两 note 在收件箱以"（教师版）/（学生版）"并列显示，发布各自走既有 `publishToLesson` 版本链。

### 2.2 V17-B · AI 修改对象放宽（D27，Renderer + 合同小改）

- `lesson-prep-context.ts` 的 `isAppGeneratedCoursewareFile` 放宽为 `isAiEditableFile`：`mimeType === 'text/markdown'`（版本模式判断保留用于版本链命名，不再作准入）；
- draft-panel 单文件修改候选列出课次全部 md（按版本链优先排序：最新版本在前）；非 md（docx/pdf/图片）维持置灰提示"仅支持修改 Markdown 文件；外部 Office 文档请用系统应用打开修改"；
- `lesson-files-section.tsx` "修改这份"入口对 md 文件启用（含外部导入 md）；课次无任何 md 时引导文案更新为"本课还没有 Markdown 课件，可先导入 md 讲义或用 AI 生成第一版课件"；
- AI 修改流（方案 → 确认 → 生成 → 对比 → 发布）全部复用 V1.5.2/V1.6 既有链路，零流程改动；修改外部导入 md 时发布产物 = `原名 · 第 N 版.md` 新文件（`publishLessonDraftVersion` 的非版本链路径，沿用现有语义），原件不动。

### 2.3 V17-C · md 人工编辑器（D28/D29，新 Renderer 组件）

- **编辑/预览切换**：`lesson-material-reader.tsx` 对 md 文件新增"编辑"按钮（只读课次/外部根目录资料不显示——外部资料编辑须先"复制到本课"成 managed 副本；已配 mineru 的增强解析按钮逻辑不动）；
- **编辑器实现**（新 `md-editor.tsx`，**零新依赖**——受控 `<textarea>` + 工具栏 + 分屏预览，不引入 CodeMirror/Monaco）：
  - **工具栏**：加粗、斜体、标题（H1–H3 下拉）、列表（有序/无序）、引用、表格模板、分隔线、**行内公式 `$…$`**、**块级公式 `$$…$$`**（模板插入光标定位）、**插图**（从本课文件选图片，插入 `![图片名](文件名)` 引用——复用阅读器已有的 `findReferencedFile` 文件名匹配渲染链，**不做 base64 内嵌**，md 体积不受图片影响）、撤销/重做（textarea 原生 + 快照栈）；
  - **字号/排版**：md 标准语法本身无字号语义，编辑器提供**字号快捷模板**（`#`/`##`/`###` 标题层级映射 + `<sub>`/`<sup>` 上下标），预览端 `styles.css` 为 `material-markdown` 已有的标题字号沿用；不引入 HTML 内联样式（渲染端 `renderInline` 出于安全不渲染任意 HTML，维持不变）；
  - **公式行级输入**：textarea 内 `$…$` 原文输入；分屏预览侧实时 KaTeX 渲染（复用 `MarkdownDocument`，无重复实现）；工具栏公式按钮弹出**LaTeX 片段速查**（分式/根号/上下标/角度/三角形等数学高频，点选插入模板）；
  - **编辑期热保存**：草稿存 localStorage（键 = fileId，250ms 防抖；写入失败静默）；进入编辑时若存在热草稿提示"恢复上次未保存编辑？恢复/丢弃"；
- **保存语义（D29 默认：存为新版本）**：保存按钮 → `files:write-version` → 成功提示"已保存为第 N+1 版（旧版保留在历史版本）"并自动选中新文件；版本链文件沿既有 ` · 第 N+1 版.md` 命名，非版本链（外部导入 md）出 `原名（编辑版）.md` 副本；
- **note_kind='manual_edit'**：人工编辑产生的课次内文件在 overview 中标注"人工编辑"（不参与 AI 修改流的 note 语义，仅作来源标识，与 AI 版本链在历史版本区并列展示）；
- **已有 note 编辑流不动**：AI 草稿保存前的编辑（draft-panel textarea）保持现状，V17-C 只覆盖"已发布 md 文件"的人工编辑。

### 2.4 V17-D · 题库自动选题 + 双版输出（D30/D31，Renderer + 生成流）

- **入口**：draft-panel 参考区新增"参考题库（AI 自动选题）"开关——未安装题库（`QuestionBankSummary.installed === false`）置灰提示"先在题库页导入 .tqbank"；开关开启时可选"目标题数（默认 5）"与"是否生成学生版"；
- **过目步（方案确认卡扩展）**：方案阶段同时执行阶段一（检索计划）+ 阶段二候选检索（Main 侧串行完成，秒级），方案确认卡新增分区显示：检索条件（tag/年级/难度/题数，AI 计划原样展示）+ 候选题列表（题号/题干预览/难度/含图标记）+ 两项反馈操作：**"调整后重新选题"**（老师输入自然语言如"再难一点/去掉尺规作图"，追加进 requirement 重新出计划）与**逐题剔除**（候选区勾掉不要的题，剔除后的候选集合固化进确认生成请求）。确认生成按（可能剔除后的）候选集执行；跳过过目直接确认 = 接受 AI 计划全集；
- **生成执行**：确认生成请求带 `bankPlan` + `dualVersion`（学生版开关）；阶段二选题写作复用 V1.6 流式链路（思考秒表 + 逐字上屏照常）；教师版 prompt 增选题规则："只能从候选题中选，不得杜撰或改编题目；每题在讲解处标注 [选自题库：tag/难度]；答案与解析集中在文末'答案与解析'区块"（为 D31 学生版剥离提供结构锚点）；
- **收件箱/发布**：双版结果在收件箱并列（教师版/学生版徽标）；发布走既有 `publishToLesson`（各自独立版本链：`讲义 · 第 N 版.md` 与 `讲义 · 第 N 版 · 学生版.md`——`publishLessonDraftVersion` 命名分支扩展）；学生版 md 中的题目即纯文本（含 `$…$` 公式），阅读器 KaTeX 沿用；
- **预算交互**：候选块字符数计入参考占用显示（"题库候选 5 题 · N 字"），总预算超 30,000 字沿用 D25 确认弹窗（列名"题库候选 N 道题（部分纳入 M 道）"）。

## 3. 安全与数据语义（不可放松项）

- **原件只读**：`files:write-version` 永远写新文件（临时文件 + 原子重命名 + importToLesson），不 UPDATE 目标行；外部根目录资料无编辑入口（先复制成 managed 副本才可编辑）；
- **AI 修改产物不覆盖原件**：D27 放宽的是"谁能当修改对象"，产物保存语义（V1.5.2 工作副本 + 版本链）零变化；
- **渲染端不新增 HTML 能力**：编辑器产出的 md 走既有 `MarkdownDocument` 渲染（无任意 HTML/内联样式通道）；插图仅文件名引用（复用 findReferencedFile 白名单匹配），不引入 base64 与外部 URL 图片；
- **题库只读**：生成侧对题库只调 search/getQuestion，不写；`.tqbank` 快照语义不变；题目进入课件即文本固化，无运行时引用；
- **Renderer 不直接访问文件系统/SQLite**：`files:read-text`/`write-version` 均为 Main 白名单通道 + 载荷守卫；题库检索执行在 Main；
- **AI Key/MinerU token 边界不变**；热保存草稿仅存 localStorage（不含密钥，不含非本文档内容）；
- **教师版标注与候选审计**：`bankSelection` 元数据入 note（计划/数量/ID），全文不重复存储。

## 4. 非目标

- 不做自动组卷、错题本、成绩分析（题库沉淀侧"个人题目区"为后续版本候选）；
- 不做含图题目进 AI 上下文（DeepSeek 无 vision；候选标注"含图"，老师可手动经既有 copyToLesson 引用）；
- 不做 Office 文档编辑/导出、不做"直接改当前版"保存语义、不引入第三方富文本/代码编辑器依赖；
- 不做学生版的本地规则剥离（固定区块刚性约束，留作后续优化）、不做题库多快照/增量换版机制（ID 稳定性已由导出器保证）。

# V1.5.5 · 正确性与健壮性加固

**日期：** 2026-08-31  
**基线：** `checkpoint-V1.5.4-pass`（已创建于 V1.5.4 最终确认提交 `954dbbd`）  
**决策：** D19（`implementation-tasks/V1_5_DECISIONS.md`）  
**任务链：** `implementation-tasks/v1.5.5-tasks/` V155-A–V155-E

## 1. 问题

2026-08-31 对 V1.5.4 收尾基线的全面分析确认了四组不影响 V1.5.4 验收、应在下一增量修复的正确性与健壮性缺口：

1. **AI 修改范围协议复用提示词字段**：`draft-panel.tsx` 把修改方式、修改对象、生成约束、老师要求与已确认方案用中文标记拼进 `aiMetadata.requirement`（≤4000 字符）。该字符串同时是发给 AI 的提示词正文与重开笔记时还原修改范围的解析协议；`parseModificationScope` 依赖 `includes` 与正则还原，老师要求中出现标记原文、或字符预算切片切断标记时还原失效。
2. **`material-library-ipc.ts` 无配套 IPC 测试**：12 个 IPC 模块中唯一缺 `*-ipc.test.ts` 的模块，而 V1.5.4 文件夹拖拽排序恰建立在它的 `reorderFolder` 通道上；通道白名单与载荷校验目前只由 Service 层测试间接保障。
3. **`MaterialLibraryService.getOverview` 条目查询含恒真条件**：`WHERE f.id IN (SELECT id FROM files WHERE deleted_at IS NULL OR deleted_at IS NOT NULL)` 恒真且冗余（JS 侧 `fileIds.has` 过滤已限定范围）。已核实："已移除文件仍出现在 overview、由渲染层分视图"是 V1.5.3.1 的有意行为，修复方向是删除误导性死 SQL，**不是**补删除过滤。
4. **健壮性缺口**：解析 worker 无单作业超时，officeparser 挂起（非报错）时索引队列停摆至重启；主窗口未设 `setWindowOpenHandler`/`will-navigate` 守卫；`publishLessonDraftVersion` 以未锚定 `LIKE '% · 第 % 版.md'` 计数版本，软删后版本号会复用；`isConstraintError` 靠错误消息字符串匹配，FK 约束（`SQLITE_CONSTRAINT_FOREIGNKEY`）误判。

## 2. 修复方案

### 2.1 AI 修改范围元数据结构化（V155-A）

双轨制：标记串继续作为 AI 提示词原样发送（提示词零变化，`DRAFT_PROMPT_VERSION` 保持 `v11-03-v1`，无 AI 行为回归）；UI 还原所需范围信息平行存入 `ai_metadata_json` 新可选键 `modification`，解析优先读结构化键。

- **合同**（`src/shared/draft-contracts.ts`）：新增 `DraftModificationScope { scopeVersion: 1; mode: 'single' | 'lesson'; baselineCount: 1..100; targetFileId? ≤128; targetName? ≤500; teacherRequirement ≤ DRAFT_REQUIREMENT_MAX_CHARS; confirmedPlan? ≤800 }` 及守卫 `isDraftModificationScope`；`DraftNoteMetadata` 增加可选键 `modification`（其守卫逐字段校验、不锁键集合，历史数据天然兼容）；`GenerateDraftRequest` 增加可选键 `modification`，`isGenerateDraftRequest` 的可选键列表必须同步加入。仅扩展现有 `drafts:generate` 载荷，同 D18 扩展 `reorderFolder` 先例，不新增通道。
- **Main**（`src/main/draft/draft-service.ts`）：`generateResolved` 透传 `input.modification`；`regenerate` 与 `requirement` 同步透传 `original.aiMetadata.modification`。
- **Renderer**（`src/renderer/draft-panel.tsx`）：`confirmPlanAndGenerate` 在 `buildModeRequirement` 之外构造结构化对象随请求发出；`parseModificationScope` 优先读 `aiMetadata.modification`，无此键回退现有标记解析（覆盖全部历史笔记，无需数据迁移）。
- **可测性抽取**（D14 复用惯例）：`buildModeRequirement`、`parseModificationScope`、`extractMarkedSection`、`modificationNodeLabel`、`buildPublishConfirmation` 移入纯模块 `src/renderer/draft-scope.ts`，组件引用，签名不变。

### 2.2 素材库 IPC 测试与 overview 查询修正（V155-B）

- 新增 `tests/material-library-ipc.test.ts`，复制 `tests/file-ipc.test.ts` 样板（`FakeIpcMain` + `TestLogger` + `initializeWorkspace` 真实临时工作区 + 真实服务栈）：注册通道集合恰为 `MATERIAL_LIBRARY_CHANNELS`（8 项）且 unregister 精确移除同一集合；额外键、负数 `sortOrder`、缺键请求在触碰服务层前被拒（`INVALID_PAYLOAD`）；未知通道 `UNKNOWN_CHANNEL`；真实错误映射（`reorderFolder` 拖入自身后代、`deleteFolder` 非空、`moveFile` 课程/学生副本、`saveExternal` 未登记根）；内部错误返回 `INTERNAL_ERROR` 通用文案、响应无栈、`logger.error` 记录 channel。
- `getOverview` 条目查询简化为 `SELECT file_id, folder_id, created_at FROM material_folder_items ORDER BY created_at, file_id`，行为零变化；`files` 查询补类型化行接口。
- 行为钉死测试（补进 `tests/material-library-service.test.ts`）：软删除独立文件仍出现在 `overview.files`（`deletedAt` 非空）且其条目保留；已挂课/已挂学生文件的条目绝不出现在 `overview.items`。

### 2.3 解析超时与窗口导航守卫（V155-C）

- `DocumentParser` 构造增加 `parseTimeoutMs?: number`（默认 `120_000`，常量 `DEFAULT_PARSE_TIMEOUT_MS`）。`runWorker` 在 `postMessage` 后启动 `unref` 定时器：触发时核对 `activeRequest.requestId`，先清 `activeRequest`、摘除 message/error/exit 监听、置空 `this.worker`（必须先于 `terminate`，exit 处理器因 `activeRequest` 已空而免疫二次触发），再 `void worker.terminate()`，以 `PARSE_TIMEOUT` 为 `parserErrorCode` reject；正常 message/error 路径 `clearTimeout`。
- 超时沿用既有 `parse_failed` 语义：contentHash 为 null 不写 `files` 行，`rebuildPending()` 重试；不引入新状态机。代价是每个挂起文件每次重建占用一个超时时长的队列头时间，但泵在超时后继续处理后续文件，不再无限卡死。
- `src/main/window-security.ts` 新增 `WebContentsLike` 接口与 `applyWindowNavigationGuard(webContents, allowedUrls)`：全局拒绝 `window.open`（`{ action: 'deny' }`）；`will-navigate` 仅放行 `allowedUrls`，其余 `preventDefault()`。`createMainWindow` 以 dev 的 `ELECTRON_RENDERER_URL` / prod 的 `pathToFileURL` 计算 index.html 地址为白名单，加载前调用。Renderer 全程不使用 `window.open`（已核实），全局 deny 无副作用。

### 2.4 版本计数与约束错误码（V155-D）

- `publishLessonDraftVersion` 由 COUNT+1 改为 MAX+1：lesson 范围查询文件名列表（**含软删除文件**，避免任何历史版本号被复用；删除后版本号留空洞是诚实的历史记录），用锚定正则 `/ · 第 (\d+) 版\.md$/u` 提取最大数字，无匹配为 1；移除未锚定 LIKE。
- `isConstraintError` 先查 better-sqlite3 错误码（`String(code).startsWith('SQLITE_CONSTRAINT')`），消息匹配降级为兜底（保留以防错误被包装丢码）。
- 树操作 O(全表) 载入维持接受：单教师规模内无碍，验收文档记录接受理由与 revisit 条件（节点数 > ~5k 时再按 `parent_id` 局部查询优化）。

## 3. 安全与数据语义

- 不新增 schema/migration、Service 或 IPC 通道；唯一载荷扩展（`drafts:generate` + `modification`）有 D18 先例，Preload 与合同的双向守卫照常覆盖。
- AI 提示词内容与 `DRAFT_PROMPT_VERSION` 不变，AI 行为无回归。
- `getOverview` 返回内容（含"已移除"文件）不变，渲染层分视图不受影响。
- 解析超时不写坏 `files` 行与搜索索引；重试语义与崩溃重试一致。
- 既有安全边界（Renderer 隔离、路径遏制、Key、原子写、备份）一律不触碰。

## 4. 非目标

- 不做带版本列的 schema v16（名称法 MAX+1 已满足单教师规模，记录在案）；
- 不改外部资料、题库、搜索与备份行为；
- 不运行 portable/installer 打包，不自动 push；
- 不改写任何已完成版本的历史状态与验收记录。

## 5. 验收

1. 结构化键优先还原，旧笔记（仅标记串）回退解析不回归；老师要求含标记原文不再污染还原；`isGenerateDraftRequest` 对新键的接受/拒绝由合同测试钉住。
2. `material-library-ipc.test.ts` 达到与其余 11 个 IPC 模块同等的验证强度；overview 行为钉死测试通过。
3. 哑 worker 注入下超时转 `parse_failed` + `PARSE_TIMEOUT`，`files` 行未写坏，后续文件队列恢复；导航守卫 deny 一切 `window.open`、拦截非白名单导航（安全基线测试覆盖）。
4. 软删 v2 后发布得 v3（非 v2）；手工导入 `… · 第 9 版.md` 后发布得 v10；FK 约束错误码正确识别且裸消息兜底仍判真。
5. 全量测试、typecheck、lint、production build、`git diff --check` 通过；代表性 Windows 冒烟（素材树拖拽、AI 修改两步流、版本发布、重启保持）通过。

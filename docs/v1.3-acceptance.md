## 3. Windows 代表性流程

### 3.1 三种排课与课程页接入

真实 Electron Renderer → Preload → Main → SQLite 完成：

1. `V13 暑假测试班`：粘贴 3 位新学生，月历选择 2026-08-24 / 08-26 / 08-29，把 16 个空课次经确认同步为 3 节；结果为 3/3 已排、每节 90 分钟。
2. `V13 规律测试班`：1 位已有学生 + 1 位新学生，创建 16 节每周 14:00 规律课；结果为 16/16 已排、每节 90 分钟。
3. `V13 暂不排课测试班`：先建课程、不关联学生，创建 16 节未排课；结果为 0/16 已排，但 16 节均保存 90 分钟。
4. 创建后均自动选中新课程，第 1 课为 Viewed / Current，顶部为可关闭成功提示并提供“进入第 1 课备课”。
5. 原“仅创建课程”和学生 / 阶段 / 课次 / 关系入口仍在；旧单节“设置时间”弹窗读取到未排课 session 的 90 分钟，并提供独立清除时间 / 清除时长。

关闭应用后直接读取隔离 SQLite：schema migration v13、`integrity_check=ok`、foreign key 0。三门课的学生 / 课次 / scheduled / duration 计数分别为 `3/3/3/3`、`2/16/16/16`、`0/16/0/16`。

### 3.2 原子失败与重试

在第二个隔离工作区中，向导最终确认页引用一个已有学生；提交前让该测试学生软删除。Main 在事务开始后重新校验并拒绝请求，界面显示“学生已删除，请先恢复”，同时保留课程名、阶段、1 节课、暂不排课和 90 分钟。

返回第 1 步把名单改为新学生后再次提交成功。最终数据库只有 1 门课程、1 个阶段、1 节课、1 个活动学生关系，证明第一次失败没有遗留新学生、半门课程或部分课次。

# V1.5.3.2 · 素材库逻辑目录与资料流转方案

**状态：** 待产品负责人确认，不进入当前 V1.5.3.1 活动链

**日期：** 2026-08-30

**归属：** V1.5.3 后续分支，暂不升级为 V1.5.4

**当前基线：** V1531-B 已实现内容；`checkpoint-V1.5.3-pass` 仍按既有规则等待最终体验确认

## 1. 背景与问题

当前页面把素材库做成了托管文件的平铺清单，并用“文档 / 图片 / 其他”作为主要分类。这样会产生三个问题：

1. 老师很难按自己的教学方式长期整理资料；
2. 课次副本、学生附件和真正可复用的素材容易混在一起；
3. “加入当前课次”没有说清资料流向，容易被理解成“把课次资料放回素材库”。

本方案确认一个基本判断：**素材库是老师自己维护的总素材库，不是所有文档的自动收集箱。**

## 2. 两棵树的产品定义

### 2.1 外部资料树

外部资料树映射老师电脑上已经存在的真实文件夹层级。

- 目录结构来自真实文件系统；
- 工作台只读浏览、打开、定位和复制；
- 不修改、移动、重命名外部原文件；
- 复制前不把整棵目录扫描进工作台；
- 它解决的是“我电脑上的资料在哪里”。

### 2.2 素材库树

素材库树是工作台内部的逻辑目录，由老师自己维护。

- 文件夹名称和层级由老师决定；
- 与 managed 文件的实际对象路径解耦；
- 老师可以新建、重命名、移动和整理逻辑目录；
- 只有老师主动导入或保存的资料才进入素材库；
- 已复制到课程或学生的独立副本不自动出现在素材库树中；
- 它解决的是“这份资料以后怎么方便复用”。

外部资料树和素材库树可以有相似的展开、收起和面包屑交互，但**不能共用同一份目录事实**。

## 3. 素材库的信息架构

左侧使用“系统入口 + 老师自建目录”的混合树：

```text
素材库
├─ 全部素材                 （系统入口）
├─ 最近使用                 （系统入口）
├─ 待整理                   （系统入口）
├─ 七年级                   （老师自建文件夹）
│  ├─ 三角形
│  ├─ 一元一次方程
│  └─ 期中复习
├─ 八年级                   （老师自建文件夹）
│  ├─ 几何
│  └─ 函数
├─ 讲义模板                 （老师自建文件夹）
└─ 题库与真题               （老师自建文件夹）
```

### 3.1 系统入口

- **全部素材：** 显示所有未删除且属于素材库的文件；
- **最近使用：** 按最近打开、复制到课次或保存时间排序；
- **待整理：** 尚未放入老师自建文件夹的素材；
- **搜索：** 跨文件夹搜索，结果必须显示所在路径。

“文档 / 图片 / 其他”降级为右侧工具栏的辅助筛选，不再充当主目录。

### 3.2 老师自建文件夹

第一版采用单父级目录：一份素材同时只属于一个逻辑文件夹。这样可以避免移动、删除和显示路径时产生歧义。

文件夹支持：

- 新建子文件夹；
- 重命名；
- 移动到其他文件夹；
- 删除空文件夹；
- 同级排序。

第一版不要求拖拽，先提供明确的“移动到”菜单或操作面板。

- 打开、所在文件夹、移动到、复制到课次、移除。

## 5. 资料流转与文案

### 5.1 外部资料 → 素材库

在外部资料中选中文件，操作命名为：

```text
保存到素材库
```

点击后先选择目标文件夹，默认建议为“待整理”。复制完成后：

- 外部原文件保持不变；
- 工作台产生一份独立 managed 原件；
- 新文件出现在所选素材库文件夹中。

### 5.2 素材库 → 课次

素材库文件行不再使用“加入当前课次”，改为：

```text
复制到课次
```

点击后选择：

```text
课程 → 阶段 → 第 N 课
```

复制完成后，课次得到独立副本，素材库原件不变。

如果老师是从某一课的备课入口打开素材库，按钮可以显示：

```text
用于本课
```

但页面仍然要显示完整目标课次名称，不能依赖“当前”二字猜测上下文。

### 5.3 课次 → 素材库

在课次资料中提供：

```text
保存为素材
```

操作时选择目标文件夹，创建新的素材库副本。它不能把课次文件直接“移动”出课次，避免破坏课程历史。

### 5.4 课次移除

课次中的“从本课移除”只作用于课次独立副本：

- 不删除素材库原件；
- 不修改外部资料；
- 不影响同一素材复制到其他课次的副本。

### 5.5 素材库删除

素材库中的“移除”采用现有软删除语义。彻底删除前仍需二次确认；已复制到课次的文件不会因此被覆盖或回溯修改。

## 6. 现有资料的首次整理

启用逻辑目录时需要一次性迁移现有数据：

1. 当前没有课程/学生关联的活动 managed 文件，放入“待整理”；
2. 已挂到课程或学生的文件不进入素材库树，只保留在各自上下文；
3. 已删除的独立素材保留原有删除状态和文件夹关系，进入“已移除素材”区域；
4. 不根据文件扩展名自动创建“文档 / 图片 / 其他”文件夹；
5. 不根据外部资料的真实路径自动复制出第二棵素材树。

这样可以保证升级后“素材库里只有老师主动保留的可复用原件”，而不会把历史课次副本重新堆回来。

## 7. 最小数据模型草案

现有 `files`、`lesson_files`、`student_files` 和 `origin_file_id` 继续保留，新增逻辑目录关系：

```text
material_folders
  id
  parent_id       可空，引用 material_folders.id
  name
  sort_order
  created_at
  updated_at
  deleted_at

material_folder_items
  folder_id
  file_id         引用 files.id
  created_at
  PRIMARY KEY (file_id)
```

`material_folder_items` 使用单父级约束，保证同一素材只出现在一个真实目录中。系统入口“全部素材 / 最近使用 / 待整理 / 搜索”不写成普通文件夹，避免与老师自建目录混淆。

文件对象实际仍由现有 managed 路径管理；移动素材只更新逻辑关系，不移动磁盘对象，不改变 `origin_file_id`，也不改变课程树。

## 8. 技术边界

这一方案一旦获批，V1.5.3.2 才允许进入数据模型增量；本方案本身不改变当前 V1.5.3.1 实现。

- Renderer 不能直接读取 SQLite 或任意文件系统；
- 目录查询、创建、重命名、移动和删除必须走类型化白名单 IPC；
- 外部资料仍然只读，路径边界不变；
- managed 文件正式写入仍使用临时文件加原子重命名；
- 课程/学生副本与素材库原件继续完全隔离；
- 不新增自动扫描、云同步、拖拽整理、批量组卷或推荐系统；
- 不把 API Key、真实教学资料或运行数据库写入 Git。

## 10. 验收标准

产品体验确认至少覆盖：

1. 从外部资料保存文件到“七年级 / 三角形”，外部原件未被改写；
2. 从素材库复制到指定课次，目标明确且生成独立副本；
3. 从课次移除副本后，素材库原件仍可用；
4. 课程副本和学生附件不出现在素材库树；
5. 新建、重命名、移动和删除空文件夹后，重启仍保持；
6. 搜索结果显示“素材库 / 七年级 / 三角形”这样的逻辑路径；
7. “文档 / 图片 / 其他”只能筛选，不会替代老师目录；
8. 历史版本、AI 工作副本、外部资料只读边界不退化。

在产品负责人确认前，不创建新的通过标签，也不改变当前 `checkpoint-V1.5.3-pass` 的既有规则。

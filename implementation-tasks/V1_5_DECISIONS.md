# 教师工作台 V1.5「教学内容工作台」冻结实施决策

**修订冻结日期：** 2026-08-25

**固定基线：** `checkpoint-V1.4-pass`

**产品主规格：** `教师工作台_V1_5_教学内容工作台_产品与实施方案.md`

## D01 · 课程管理与教学内容分开

- 左侧“我的课程”改为“课程”。
- 左侧新增“教学内容”，移除独立“备课”入口。
- “课程”管理课程事实；“教学内容”统一承载课件、AI 备课和修改记录。
- 不新增独立“课件”主导航或第二棵课程数据树。

## D02 · 教学内容共享一个 lesson 上下文

- 工作台固定为“课件 / AI 备课 / 修改记录”三个分区。
- course、period、lesson 在分区间保持不变。
- 打开草稿可切换到草稿所属 lesson 和“备课”；已保存成果回到“课件”查看。
- 所有浏览和备课入口都不得隐式改变 Current Lesson。

## D03 · 课程 / 课次目录不常驻

- 顶部显示当前课程、阶段和课次。
- “切换课程 / 课次”打开临时左侧抽屉，选择完成后收回。
- 提供上一课和下一课作为连续浏览捷径。
- 不允许同时常驻课程课次目录和本课课件目录。

## D04 · 正文宽度是验收条件

- 课件分区只常驻全局主导航、本课 220–260px 课件目录和正文。
- 约 1200px 代表性窗口中，正文使用扣除前两者后的全部剩余宽度，阅读面积不得小于现有课次资料阅读页。
- “沉浸阅读”可收起本课课件目录；窄窗口不得产生页面级横向溢出。

## D05 · 课程、学生与直接入口使用同一工作台

- 课程课次的“查看教学内容”和双击进入“课件”；明确备课动作进入“备课”。
- 学生先进入统一课程页，再进入同一教学内容工作台，并保留返回学生上下文。
- 直接打开“教学内容”恢复会话内最近有效位置；没有位置时显示选择空状态。

## D06 · 临时导航状态不写数据库

- 导航目标至少包含 courseId、lessonId、section 和可选 originStudentId。
- 最近浏览位置只保留在本次 Renderer 会话，不修改 course_progress。
- Current Lesson、Viewed Lesson 和 Prep Lesson 继续严格分离。

## D07 · 复用既有内核

- 不新增 schema、migration 或新草稿模型。
- 默认不新增 Service 或 IPC；若现有白名单能力不足必须停止并重新确认。
- 复用 LessonMaterialReader、DraftPanel、LessonPrepContext、ManagedFileService、AI、Search 和 Backup。
- 不加入独立课件库、拖拽整理、云同步、成绩、推荐、组卷或新 AI Workflow。

## D08 · 可见操作是主路径

- 双击只是“查看教学内容”的效率捷径，不能成为唯一入口。
- “查看教学内容”“开始/继续备课”“切换课程/课次”“返回课程/学生”和三个分区必须可聚焦、可单击。
- 文案统一使用“课程”“教学内容”“课件”“AI 备课”“修改记录”。

## D09 · 增量版本命名与边界（2026-08-29 按产品负责人裁决修订）

- V1.5 是版本基线，最终通过标签为 `checkpoint-V1.5-pass`。
- 本轮「教学内容工作台」实施链 V15-01～V15-03 作为整体记为 V1.5.1（已完成）。
- 下一轮增量「AI 协作修改工作区」命名为 V1.5.2，不写成模糊的“V1.5 后续”，也不是 V1.6。
- 未来同类增量按 V1.5.3、V1.5.4 顺序递增。
- 当前 V15-01～V15-03 验收链保持不变；V1.5.2 需在 V15-03 最终体验确认后另行进入实施链。

## D10 · 草稿箱不再是教学内容固定分区

- 教学内容固定分区调整为“课件 / AI 备课 / 修改记录”。
- 不新增“草稿箱”左侧主导航，不建立独立全局草稿库。
- 既有 draft 数据继续兼容使用，但在 Renderer 中按“当前工作副本”和“修改记录”解释，不复制、不迁移、不改变既有事实。

## D11 · 正式课件与当前工作副本分离

- 正式课件是老师确认后可用于上课的版本。
- 当前工作副本承载老师和 AI 的未发布修改，任何时间可以保存。
- “保存当前进度”不得改变正式课件；“保存为新版本”才发布新的正式课件。
- AI 不得直接覆盖正式课件或原始资料。

## D12 · AI 先提方案，再生成内容

- 已有课件改进流程必须先收集老师的修改意图和明确参考范围。
- AI 先输出可审阅的修改方案；老师确认后才生成新工作副本。
- 新旧内容对比、手动编辑、重新生成、放弃和恢复都属于同一个 lesson 的修改会话。

## D13 · 修改记录属于课次上下文

- 修改记录至少能追溯老师要求、参考内容、AI 方案、生成节点、保存节点和发布节点。
- 修改记录不成为全局主导航；打开记录时自动恢复对应 course / period / lesson。
- 未发布节点标记为“修改中”，正式发布节点标记为“已确认”。

## D14 · 后续实现优先复用既有内核

- 后续 AI 协作优先复用现有 DraftPanel、LessonPrepContext、notes 生命周期、AI Gateway、ManagedFileService 和 LessonMaterialReader。
- 默认不新增 schema、migration、Service 或 IPC；若“工作副本/修改记录/版本发布”无法在既有事实和安全能力上实现，必须先重新确认范围。

## D15 · V1.5.2 验收分层

- 自动门使用固定 fake provider，验证状态机、失败路径与安全边界，保证可重复；
- 开发验收使用"中继式 AI"：本地 OpenAI-compatible 服务挂起请求并暴露完整 prompt，由实施代理按真实语义现写修改方案与内容回填，检验 prompt 组装、两步确认流与内容质量；每次相关改动至少执行一轮并留痕；
- 最终体验确认由产品负责人以真实 API Key 完成至少一轮完整备课；三层全部通过才算验收。

## D16 · V1.5.3 课件动作化布局（产品负责人确认，设计基准 tmp/v1.5.3-mockup.png）

- 教学内容仅保留"课件 / 修改记录"两个分区；AI 入口是课件分区的动作按钮（无课件=AI 新建备课，有课件=✦AI 修改），不再是并列 tab；
- 工作台两栏：左=参考资料+本课修改记录；右=**修改要求提示词框常驻**+方案审阅+对比与发布；顶栏可"退出修改，回到课件"；
- 课件列表每个内容只显示一个当前版（"标题 · 第 N 版 · 当前"），历史收进「历史版本（N）」折叠入口；正文默认当前版；
- 生成结果呈现：✦AI 修改说明摘要卡 + 视图切换（并排对照｜修订标注｜仅看新版）；修订标注为 Word 修订式红绿高亮，不是代码式 diff；
- 全部复用既有 AI/notes/publish 能力，不新增 schema、migration、Service 或 IPC。

## D17 · V1.5.3.1 AI 修改范围分流（产品负责人确认，2026-08-30）

- V1.5.3.1 属于 V1.5.3 最终验收前的小版本修正，不升级 V1.5.4；完成后仍以 `checkpoint-V1.5.3-pass` 作为最终通过标签；
- 已有课件时明确区分“修改当前文件”和“整课重做”：前者锁定一份可读文档，后者自动使用当前正式版本（没有正式版本时使用本课现有可读内容）；
- “修改对象”和“补充参考”必须分离：单选/自动范围决定改什么，复选框只用于可选参考，不再同时承担修改目标、参考依据和生成产物三种语义；
- 无课件时继续使用“AI 新建备课”，只有该状态保留“生成讲义 / 例题 / 作业”快速动作；已有课件的两种修改模式必须先生成并审阅模式化修改方案；
- 整课重做生成一份完整课件 Markdown 新版本，正文内部包含讲义、例题、练习和作业板块；不新增多文件课件套件、批量原子发布或版本组；
- 模式与目标通过 Renderer 会话状态及既有 `aiMetadata.requirement + sources` 恢复，不新增 schema、migration、Service 或 IPC；
- 设计与验收细节以 `docs/v1.5.3.1-design.md` 和 `implementation-tasks/v1.5.3.1-tasks/` 为准。

## D18 · V1.5.4 素材库树交互（产品负责人确认，2026-08-31）

- 素材库“我的文件夹”必须采用完整桌面树交互：有子目录的文件夹可独立展开/收起，展开状态不与当前选中目录绑定；
- 顶部“新建文件夹”保留为全局效率入口，同时在“我的文件夹”和文件夹右键菜单提供顶层/子文件夹就地创建；
- 素材文件可拖入任意自建文件夹，也可拖回“待整理”；文件夹可拖入其他文件夹成为子目录，并可在同级或跨级重新排序；
- 文件夹拖拽必须阻止拖入自身或后代；所有拖拽只改变 SQLite 中的逻辑目录关系，不移动、覆盖或改名底层 managed 文件；
- 文件和文件夹均提供应用内右键菜单。文件菜单覆盖打开、定位、复制到课次、移动到目录/待整理和移除；文件夹菜单覆盖新建子文件夹、重命名和删除；
- 本增量不做外部资料树与素材库之间的跨页面拖拽、不接管 Windows 资源管理器拖放、不新增批量选择、云同步或物理文件整理；
- 不新增 schema/migration 或 IPC 通道。复用现有 `material-library:move-file` 与 `material-library:reorder-folder`，后者扩展 `parentId` 并由 Main 完成循环校验和原子排序。

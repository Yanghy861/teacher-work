# 教师工作台 Lean V1 决策

> 历史说明：Lean V1 已在 `checkpoint-L12-pass` 完成。本文件继续记录 V1 裁决；当前 V1.1 增量以 `V1_1_DECISIONS.md` 为准。

本文件自 2026-08-20 起取代旧 T09–T42 的企业级实施假设。历史 T01–T08 与其审核记录继续有效；后续只执行 `lean-tasks/L01`–`L12`。

## 1. 目标优先级

Lean V1 只保证一个老师在一台 Windows 电脑上完成三条主流程：

1. 建课程/学生/课次，导入、复制、打开和整理资料；
2. 搜索文件名、标题、笔记以及常见文档正文；
3. 选择资料，生成并保存可编辑的讲义、例题和作业草稿。

备份恢复和 Windows 可运行属于交付底线。除此之外，自动化程度、极端并发、精确续跑、复杂进度、通用抽象和罕见边界不能阻塞 V1。

## 2. 强制简化规则

- 实现代价明显高于单机自用收益时，代理应选择更简单的等价路径，并在进度记录中写明取舍；不需要为了旧任务文字保持复杂方案。
- 手动刷新/重试/确认优先于实时监听、后台自动恢复和复杂状态机。
- 一个顺序后台 Worker 优先于 Worker Pool、优先级队列、持久调度器和跨库事务协议。
- 失败后按文件或按一次生成重新执行，优先于精确恢复到内部步骤或百分比。
- 代表性真实 smoke + 核心自动测试优先于大规模矩阵、每个边界强杀和重复真机验收。
- UI 可先用按钮、菜单和普通列表；拖拽、完整键盘等价操作、大数据量优化和精细动画均为 Later。
- 非核心功能若需要新增子系统，可直接移入 Later；只有改变三条主流程或下述硬边界时才需要用户重新决策。

## 3. 仍然不可放松的硬边界

- 不删除、覆盖或自动迁移老师原资料；AI 输出只保存为新草稿。
- Renderer 不直接访问 SQLite、Node API、任意文件系统路径或已保存的 API Key。
- managed 正式文件采用受控对象目录；写入先到临时文件，再完成/校验后重命名。
- 导入、打开、恢复和解包必须做基本路径边界检查，不能逃出用户选定目录。
- API Key 不明文落盘、不进入日志、仓库或备份；安全存储不可用时只允许本次会话使用或拒绝持久化。
- 长解析、Hash 和批量索引不能在 Electron Main 同步执行。
- 本地 Git 保留；不得自动 push、添加远程、提交秘密或真实教学资料。

## 4. 明确移入 Later

- external roots 的后台扫描、missing 跟踪、整体重定位和只读目录管理；V1 通过文件选择器导入/复制。
- Chokidar 实时 watcher 的生产接入；V1 依靠启动、焦点返回、重新打开和手动刷新核对。
- 拖拽树、1000+ 节点专项优化、所有操作的键盘等价入口。
- 持久索引任务队列、优先级、精确进度恢复、通用 Worker Pool；启动时按 Hash 重新排队即可。
- PDF/DOCX/PPTX/XLSX 四套独立实施项目；统一 Adapter 一次完成。
- AI 多步骤 Workflow、强杀后精确续步、逐片段 content_hash source manifest；每次生成独立保存。
- 并发写入期间的无停顿备份、增量/加密/云备份、完整孤儿修复系统和恶意压缩包攻防矩阵。
- 自动升级器和多版本升级矩阵；V1 只需一种可安装或便携交付方式，并保证卸载不删工作区。

## 5. 验证强度

- 普通里程碑：相关自动测试 + typecheck + lint；只有影响构建时才运行 build。
- 阶段闸门 `L04/L07/L10/L12`：完整测试、typecheck、lint、production build，加一条代表性 Windows/真实流程 smoke。
- 只对可能造成资料损坏、路径越界或秘密泄漏的代码写故障/负向测试；普通 UI 不要求穷举故障注入。
- 非核心限制应写入“已知限制/Later”，不得仅因未覆盖罕见场景标 `BLOCKED`。

## 6. 真正阻塞条件

只有以下情况可以停止为 `BLOCKED`：核心 happy path 无法运行；存在资料损坏/覆盖风险；存在路径越界或秘密泄漏；缺少完成当前核心流程必需的用户权限/凭据；或需要用户决定会明显改变产品主流程。可用简单替代解决的问题不是阻塞。

# T06 · Spike C：Office/WPS 刷新核对与保存事件

**前置：** T01–T03；Windows 真机及实际支持的 Office/WPS。  
**目标：** 证明工作台不依赖 Office/WPS 的实时保存事件也能发现文件变化；确定刷新核对、稳定检测、Hash 去重和任务合并策略。

## 实现范围

- 建立刷新核对实验工具：不接收 watcher 事件也能在启动核对、工作台重新获得焦点、重新打开文件或手动刷新时比较稳定文件与已知 Hash；
- 对 PPTX、DOCX、XLSX 做代表性的真实 WPS 普通保存/打开未改验证，确认文件最终可读；不穷举 WPS 自动恢复、保存中退出等内部时序；
- 实现并实验：多次 size+mtime 稳定采样、可读检查、Hash 去重、同 file_id 单任务合并；同一新 Hash 只能产生一次“需要重建”决定；
- Chokidar watcher 作为可选加速器保留。原始事件只能标 dirty，不能成为变化检测的唯一来源，也不能直接触发 Hash、解析或索引；
- 验证 watcher 完全漏报时，显式刷新核对仍能发现真实内容变化；重复刷新、重复事件或并发触发不会产生重复任务；
- 结果写入 `docs/spike-results.md` 的 Spike C 章节，包括刷新触发点、最坏一致性边界、真实应用/版本及 watcher 已观察到的事件特征。

## 不做

不接入正式索引器；不把固定等待 2～3 秒写成唯一判据；不要求证明 Office/WPS 自动恢复、大文件保存和保存中退出的全部内部事件序列；不声称未实测的软件可用。

## 验收

- 自动化核对证明：即使没有 watcher 事件，启动/焦点返回/重新打开/手动刷新中的任一触发都能通过稳定读取和 Hash 比较发现变化；
- 一次内容变化最终恰好产生一次“需要重建”决定，Hash 未变不重建，并发刷新不会排出多份同文件任务；
- 至少完成实际支持应用的一轮普通保存和打开未改真机验证，记录版本与格式；已有 DOCX/PPTX/XLSX 真实普通保存证据可以复用；
- 自动恢复、大文件保存和保存中退出不是 T06/T08 的阻塞条件。若未来产品要承诺这些场景的实时感知或性能，再作为专项测试处理。

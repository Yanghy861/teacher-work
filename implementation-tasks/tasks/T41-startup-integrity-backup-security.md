# T41 · 启动完整性、tmp/孤儿处理与备份安全审计

**前置：** T39、T40、T31。  
**目标：** 把文件系统与数据库的可恢复边缘情况收口，避免静默丢资料。

## 实现范围

- 启动时识别明显过期 `.tmp`；只在解析到受控工作区内且满足年龄/命名规则时清理，记录结果；
- 检测“有数据库记录但对象缺失/不可读”并标 error/missing，禁止静默删记录；
- 检测“对象存在但无数据库记录”的孤儿，默认报告/隔离候选，不自动永久删除；
- 提供轻量工作区完整性检查：数据库 integrity、schema、managed 路径、external root 状态、索引可重建状态；
- 启动时统一恢复 index processing、AI running 中断状态，并保持已完成步骤；
- 正常退出时若有索引或 AI 任务，显示“等待完成 / 退出稍后继续”；强杀安全仍不得依赖此提示；
- 对正常备份包做白名单审计，证明无 search.db、cache、日志、API Key/密文；
- 故障报告不得包含秘密或文档正文。

## 不做

完整 file_ops journal、全文件 SHA-256 manifest、自动永久删除孤儿、修复 external 原件。

## 验收

- tmp/孤儿/缺失/数据库损坏分别有安全 fixture 和人工可理解报告；
- 清理逻辑有绝对路径边界测试，绝不会越过当前工作区；
- 覆盖原规格测试 15、16、28，并复核 7、12、13 的启动恢复；
- 用户可在不运行 AI 的情况下完成完整性检查。

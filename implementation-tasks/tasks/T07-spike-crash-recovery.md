# T07 · Spike D：强杀与恢复

**前置：** T01–T03；可在临时工作区启动/强杀测试进程。  
**目标：** 在正式业务代码前验证“任务随时被中断”的工程策略。

## 实现范围

- 建立只操作临时工作区的 crash harness，可在预设故障点启动子进程并强杀；
- 分别模拟文件复制到 tmp、校验/rename、数据库事务、Hash、解析、索引写入期间退出；
- 验证重启后的 tmp 识别、正式文件完整性、事务回滚、processing → pending、已完成项不重做；
- 验证损坏/不可读输入只使单项失败，不阻塞后续队列；
- 记录 Windows 上原子 rename/文件占用的实际限制；
- 将场景、故障点、观察结果和生产建议写入 `docs/spike-results.md` 的 Spike D 章节。

## 不做

不在真实用户目录做破坏实验，不做 token 级 AI 恢复，不提前实现完整生产队列。

## 验收

- crash 测试可自动重复，目标临时路径有严格校验；
- 所有“正式成功”状态都对应完整文件和已提交事务，半成品不会伪装成功；
- 报告明确哪些操作顺序可进入生产、哪些仍有风险；无法真实强杀验证则标 `BLOCKED`。

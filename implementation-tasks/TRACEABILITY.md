# Lean V1 规格与任务追踪

## 核心能力覆盖

| 用户能力/硬边界 | 里程碑 |
|---|---|
| Electron/React/TS、工作区、SQLite、安全 IPC | 历史 T01–T03 |
| 解析、中文/数学搜索、刷新与恢复风险证据 | 历史 T04–T08 |
| 课程、学生、课次、基础树与逻辑关系 | L01、L04 |
| managed 文件、素材副本、打开与刷新 | L02–L04 |
| search.db、中文/数学检索、统一解析、后台顺序索引 | L05–L07 |
| Key 安全、兼容 AI Gateway、选资料与三类草稿 | L08–L10 |
| 空闲态备份、新目录恢复、Windows 交付 | L11–L12 |

## Lean V1 必证场景

| 场景 | 主责任里程碑 |
|---|---|
| 树移动/重命名不移动 managed 物理文件 | L01–L04 |
| 素材加入不同课次后形成独立副本 | L02、L04 |
| 导入失败不留下正式半文件，路径不能逃逸工作区 | L02、L04 |
| 修改文件后通过重新打开/焦点返回/手动刷新发现变化 | L03–L04 |
| 中文、英文、题号和常见数学表达式能检索 | L05、L07 |
| `no_text` 与 `parse_failed` 可区分，单文件失败不阻塞其他文件 | L06–L07 |
| 删除 `search.db` 后可重新扫描重建，业务资料不丢 | L07 |
| 批量解析/索引不阻塞 Electron Main | L06–L07 |
| Renderer 无法直接访问 Node/SQLite/文件系统/Key | L04、L07、L10、L12 |
| 未选择的整份资料不会被发送给 AI | L09–L10 |
| AI 输出保存为草稿，不覆盖老师原资料 | L09–L10 |
| API Key 不进数据库、日志、Git 或备份 | L08、L10–L12 |
| 备份恢复到新目录后核心业务数据和 managed 文件可用 | L11–L12 |

## 明确不再要求的旧验收

external roots 扫描/重定位、watcher 事件穷举、索引任务持久化与精确续传、Worker 池、格式独立生产框架、AI 步骤状态机与内容哈希清单、在线并发备份与孤儿修复、自动更新和大规模交互矩阵均进入 Later，不得用它们阻塞 Lean V1。
